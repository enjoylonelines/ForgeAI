# ADR-011: 배포 게이트 (승격 기준) 정의

**상태:** 채택 (기준값 미확정)

---

## 맥락

모델을 "배포해도 되는가"에 대한 판단이 담당자의 감이나 직관에 의존하면  
재학습·버전 교체 시 성능 회귀를 사전에 막을 수 없다.  
또한 포트폴리오 관점에서 "이 모델을 어떤 기준으로 배포 결정하는가"를 설명할 수 없으면  
운영 신뢰성 설계가 없는 것과 같다.

배포 게이트는 "감이 아니라 기준으로 배포한다"는 원칙을 코드화한 것이다.

---

## 고려한 대안

### 대안 A: 담당자 주관 판단

- 매 재학습마다 수치를 보고 담당자가 배포 결정
- **배제 이유:** 기준이 없으면 "이전보다 나빠졌는가"를 사후에야 알 수 있다.  
  야간 배포·자동화 파이프라인에서는 검토자가 없을 수 있음.

### 대안 B: 단일 지표 임계값 (PR-AUC만)

- PR-AUC ≥ X 충족 시 배포
- **배제 이유:** 확률 보정(ECE) 없이 PR-AUC만 좋은 모델은 임계값 설정 시 실제 빈도와 불일치.  
  재현성 미확인 상태에서 배포하면 동일 코드가 다른 환경에서 다른 결과를 낸다.

### 대안 C: 다중 조건 AND 게이트 — 채택

- 정확도 · 보정 · 재현성 · 회귀 테스트를 모두 통과해야 배포 승인
- 하나라도 실패하면 이전 버전 유지

---

## 결정

다음 조건을 **AND**로 모두 충족해야 배포를 승인한다:

```
배포 승인 조건:
  1. PR-AUC          ≥ [___]    ← 운영점 결정 후 확정 (현재 기준: XGBoost 0.830)
  2. 운영점 Recall   ≥ [___]    ← PR 곡선 측정 후 현장 FN:FP 비용 기반 결정
  3. ECE             ≤ [___]    ← 확률 보정 실험 후 (ADR-004)
  4. 재현성 확인               ← 동일 시드·동일 데이터 → 동일 수치 (scripts/baseline_classifier.py)
  5. 회귀 테스트 통과          ← 이전 버전 대비 PR-AUC 하락 없음 (scripts/regression_test.py)
```

**빈칸 채우기 순서:**
1. 운영점 설정 (ADR-003 빈칸 선행) → 기준 2 확정
2. 확률 보정 실험 (ADR-004) → 기준 3 확정
3. 기준 1은 확정된 기준 2·3 달성 가능한 수준으로 소급 결정

---

## 이유 (인과)

**모델 변동성 관리의 핵심은 "사전 정의된 기준"이다.**

재학습이 반복될수록 (운영 데이터 추가, 피처 엔지니어링, 하이퍼파라미터 탐색) 의도치 않은 회귀가 발생한다.  
게이트가 없으면 배포 후 현장에서 성능 저하를 발견하게 된다.  
이 게이트가 통과 기준인 동시에 "이전 버전보다 나쁘면 배포 금지"라는 자동 방어선이다.

---

## 포기한 것 / 트레이드오프

엄격한 게이트는 실험 속도를 늦춘다.  
기준 1~3이 모두 [___]인 현재는 게이트가 구조만 존재하고 수치 강제는 없다.  
빈칸을 채우기 전에는 재현성(기준 4)과 회귀 테스트(기준 5)만 자동 점검할 수 있다.
