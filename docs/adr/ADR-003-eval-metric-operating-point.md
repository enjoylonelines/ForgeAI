# ADR-003: 평가지표 선택 및 운영점 설정

**상태:** 채택 (운영점은 검토중)

---

## 맥락

제조 이상 탐지에서 "어떤 지표로 모델을 평가하는가"는 "어떤 실패를 더 용납할 수 없는가"의 공학적 결정이다.  
AI4I 2020 기준 고장 비율 3.39% 환경에서 지표 선택을 잘못하면 쓸모없는 모델을 좋은 모델로 착각한다.

---

## 고려한 대안

### 대안 A: Accuracy

- "항상 정상" Dummy 모델이 Accuracy 96.6%
- 고장 Recall 0.000 — 고장을 하나도 잡지 못함
- **배제 이유:** 클래스 불균형 환경에서 완전히 무의미

### 대안 B: ROC-AUC

- 불균형 클래스에서 ROC-AUC는 낙관적으로 편향됨 (음성 클래스가 지배)
- Dummy의 ROC-AUC ≈ 0.50 → 구별 어려움
- **배제 이유:** 음성 클래스(정상) 수가 압도적으로 많으면 TN이 분모에 들어가 FPR이 과소평가됨

### 대안 C: PR-AUC (Precision-Recall AUC) — 채택

- 양성 클래스(고장)에만 집중. 음성 클래스 수에 무관
- Dummy의 PR-AUC = 0.034 → 실제 성능 차이가 명확히 드러남
- 임계값 이동 없이 전 범위 성능을 단일 수치로 요약

### 대안 D: F1-score

- 단일 임계값 기준 → 임계값 선택이 지표에 영향을 줌
- PR-AUC의 보완 지표로는 유용, 단독 헤드라인은 부적절

---

## 결정

**헤드라인 지표:** PR-AUC  
**운영 지표 (임계값 결정 후):** 고장 클래스 Recall, Precision, F1  
**보조 지표:** confusion matrix (FN/FP 절대 수치)

**지표 선택 이유:**
```
비용 비대칭: FN(미탐) >> FP(과탐)
  - FN: 고장을 탐지하지 못함 → 설비 파손, 라인 정지, 안전 사고
  - FP: 정상을 고장으로 경보 → 불필요한 점검 비용 (≈ 1~2시간 인건비)

따라서 Recall을 우선 최대화하되, 허용 가능한 Precision 하한을 결정해야 한다.
→ 운영점은 "Recall ≥ X에서 Precision이 얼마인가"로 설정.
```

---

## 포기한 것 / 트레이드오프

PR-AUC를 높이면 낮은 임계값에서 과탐(FP)이 늘어난다.  
현장에서 FP 경보가 너무 많으면 경보 피로(alert fatigue)로 인해 실제 고장 경보도 무시된다.  
따라서 Recall 최대화만이 목표가 아니라, "경보 피로를 유발하지 않는 FP 수준"과의 균형이 필요하다.  
이 균형점은 현장 운영 조건 없이는 결정할 수 없다 → 운영점은 빈칸.
