# ADR-001: 검증 데이터 AI4I 2020 → SECOM 이전

**상태:** 검토중

---

## 맥락

현재 ML 베이스라인과 rule engine 임계값은 모두 UCI AI4I 2020 데이터셋 기반이다.  
AI4I 2020은 실제 공장 데이터가 아닌 시뮬레이션 데이터 (논문 생성 데이터, 10,000행)이며,  
고장 모드 레이블(TWF/HDF/PWF/OSF/RNF)이 이미 코딩되어 있어  
rule engine 임계값과 피처 선택이 데이터셋에 최적화되는 과적합 위험이 있다.

SECOM 데이터셋(`data/raw/secom/secom.csv`, `secom_labels.csv`)은  
실제 반도체 웨이퍼 공정 데이터로, 1,567행, 590개 피처, 결측치 다수, 수율 불량 레이블 (1=불량, -1=양호)이다.  
`secom_labels.csv`에는 행마다 타임스탬프가 있어 (`"19/07/2008 11:55:00"` 형식) 시간순 분할이 가능하다.  
고차원·결측·현실 노이즈 환경에서의 이상 탐지 능력을 검증하기에 적합하다.

---

## 고려한 대안

### 대안 A: AI4I 유지

- **장점:** 고장 모드 레이블이 명확, rule engine 조건식이 데이터와 1:1 매핑, 재현성 높음
- **단점:** 시뮬레이션 데이터, 현실 노이즈 미반영. 면접관 입장에서 "실제 제조 데이터를 다뤄봤는가"에 대한 답 약함

### 대안 B: SECOM으로 완전 이전

- **장점:** 현실 반도체 공정 데이터, 고차원 피처 선택·결측 처리·클래스 불균형 모두 포함
- **단점:** 고장 모드 세분화 레이블 없음 (pass/fail 이진 레이블만), rule engine 조건식 적용 불가

### 대안 C (현재 방향): AI4I 파이프라인 유지 + SECOM 별도 베이스라인 추가

- **장점:** AI4I의 FDC 파이프라인(rule engine + LLM 에이전트)을 살리면서, SECOM으로 ML 이상 탐지 범용성 검증
- **단점:** 두 데이터셋을 별도로 관리해야 함. SECOM에서는 rule engine 조건식 적용 불가

---

## 결정

대안 C — AI4I 기반 FDC·RCA 파이프라인은 유지하고, SECOM에서 ML 베이스라인(이진 수율 예측)을 별도로 측정한다.

---

## 이유

AI4I의 가치는 고장 모드 레이블 덕분에 "규칙 기반 FDC + LLM RCA"라는 2-tier 설계를 명확히 보여준다는 데 있다.  
SECOM은 이 파이프라인에 편입시키기 어렵지만(레이블 불일치), ML 이상 탐지 자체의 일반화 능력을 보여주는 데 적합하다.  
두 데이터셋을 분리해 각각의 목적으로 사용하는 것이 혼합보다 설계 의도를 명확히 전달한다.

---

## 포기한 것 / 트레이드오프

SECOM을 파이프라인에 통합하지 않으므로 "SECOM 환경에서 LLM 에이전트가 어떻게 작동하는가"는 검증 불가.  
보완: SECOM 베이스라인 수치(PR-AUC, Recall)를 `scripts/`에 별도 스크립트로 측정하고 README에 병기한다.

---

## 결과 / 검증

**SECOM 베이스라인 실측값** (`scripts/secom_baseline_classifier.py`, 시간순 분할):

| 모델 | PR-AUC | 불량 Recall | 불량 Precision |
|------|--------|------------|---------------|
| Dummy (항상 양호) | 0.054 | 0.000 | 0.000 |
| Random Forest | 0.070 | 0.000 | 0.000 |
| XGBoost | 0.081 | 0.000 | 0.000 |

- 피처: 590개 → 결측 50%+ 제거(28개) + 분산 0 제거(116개) → **446개**
- 결측 처리: median imputation (train fit → test transform, 누수 없음)
- Train: 1,253행 (불량 87개 / 6.94%), Test: 314행 (불량 **17개** / 5.41%)

**해석:** RF·XGBoost 모두 불량을 하나도 탐지하지 못했다 (Recall 0.000).  
원인은 두 가지가 복합적이다:
1. **test셋 불량 절대 수 17개** — 임계값 0.5 기준에서 17개 중 단 1개도 초과하지 못한 것으로 추정. PR-AUC는 전 임계값에서 0.08로 Dummy(0.054) 대비 소폭 높아 어느 정도 순위 구분은 되고 있다.
2. **개념 드리프트 가능성** — 시간순 분할이므로 train(7~10월 초)과 test(10월 초~중순) 간 공정 조건 변화가 있을 수 있다. 랜덤 분할 대비 성능이 낮은 것이 예상된 결과다.

→ 이 결과 자체가 "SECOM에서 raw 베이스라인이 얼마나 어려운가"를 보여주는 정직한 데이터다.  
→ 피처 중요도 기반 상위 N개 선택 + 임계값 조정 후 재측정이 다음 단계.  
→ ADR-002 빈칸은 이 수치로 채워졌다.
