# SECOM 표준 처방 실험 기록 (secom-standard-remedies)

> 위치 제안: `docs/experiments/secom-standard-remedies.md`
> 작성일: 2026-07-08
> 목적: "SECOM에서 XGBoost 신호를 표준 기법으로 살릴 수 있는가"에 대한 3단계 실측 기록.
> 이 문서는 이미 수행한 실험의 수치를 기록한 것이다. 결론은 G2 결정(SECOM = 약신호 스트레스 테스트)의 근거가 됐다.

---

## 0. 재현 조건

- 데이터: `data/raw/secom/secom.csv` (1,567행 × 590 무명 피처), `secom_labels.csv` (불량 104건, 6.64%)
- 전처리: **리포 스크립트(`scripts/secom_baseline_classifier.py`)와 동일** — 결측률 50% 초과 컬럼 28개 제거, 분산 0 컬럼 116개 제거 → 446피처. 남은 결측은 train의 중앙값으로 채움 (test에는 train 중앙값 적용, 누수 차단)
- 분할: **시간순 80/20** (ADR-002). 분할 기준 시각 2008-10-02 19:25:00. Train 1,253행(불량 87, 6.94%) / Test 314행(불량 17, 5.41%)
- 모델: XGBoost, `scale_pos_weight=13.40` (train 클래스 비율), `random_state=42`
- 환경: 샌드박스에서 pip 설치한 xgboost·scikit-learn (리포 코드는 수정하지 않음). 실험 2·3의 튜닝은 전부 train 내부에서만 수행 (실험 2: train 뒤쪽 20%를 검증셋으로, 실험 3: 시간순 3-fold CV). test는 각 실험의 마지막 1회 평가에만 사용

---

## 1. 실험 1 — 리포 베이스라인 재현 (기본 임계값 0.5)

리포 스크립트를 그대로 실행. ADR-001 기재 수치와 일치함을 확인.

| 모델 | PR-AUC | 불량 Recall | 불량 Precision | Accuracy |
|---|---|---|---|---|
| Dummy (항상 양호) | 0.0541 | 0.000 | 0.000 | 0.9459 |
| Random Forest (class_weight=balanced) | 0.0810 | 0.000 | 0.000 | 0.9459 |
| XGBoost (scale_pos_weight=13.4) | **0.0750** | **0.000** | 0.000 | 0.9459 |

관찰: 불균형 보정(scale_pos_weight)이 이미 들어가 있는데도, 기본 임계값 0.5에서는 두 모델 모두 단 1건도 불량으로 예측하지 않는다 (test 314건 중 경보 0건).

## 2. 실험 2 — 임계값 튜닝 + 확률 보정

**임계값 튜닝**: train 뒤쪽 20%를 검증셋으로 잘라, "Recall ≥ 0.7을 만족하는 최대 Precision" 기준으로 임계값을 골랐다. 선택된 값: **0.0019** (기본 0.5가 얼마나 비현실적인지 보여주는 수치다).

test 결과 (기저율 = 17/314 = 0.054):

| 임계값 | Recall | Precision | 경보 수 (FP 포함) | 비고 |
|---|---|---|---|---|
| 0.500 | 0.000 | 0.000 | 0 | 기본값 (실험 1 재현) |
| 0.002 | 0.529 | 0.064 | 141 | 검증셋 튜닝값 — **314건 중 141건 경보, 그중 진짜 9건** |
| 0.300 | 0.000 | 0.000 | 2 | |
| 0.100 | 0.000 | 0.000 | 6 | |

PR 곡선에서 도달 가능한 운영점 (test):

| 목표 | 달성 가능한 최대 Precision | 기저율 대비 |
|---|---|---|
| Recall ≥ 0.5 | 0.070 | 1.30배 |
| Recall ≥ 0.7 | 0.067 | 1.24배 |
| Recall ≥ 0.9 | 0.055 | **1.01배 (사실상 무작위)** |

**확률 보정** (CalibratedClassifierCV, cv=3) — Brier score, 낮을수록 좋음:

| 방법 | Brier | PR-AUC |
|---|---|---|
| 무보정 XGBoost | 0.0545 | 0.0750 |
| Isotonic | 0.0525 | 0.0525 |
| Sigmoid (Platt) | 0.0546 | 0.0409 |
| **비교 기준: "항상 5.4%"라고만 답하기** | **0.0512** | — |

관찰: 보정을 해도 "항상 기저율만 말하는 예측"보다 Brier가 나쁘다. 보정된 확률에 담긴 정보량이 사실상 없다는 뜻이다.

## 3. 실험 3 — 하이퍼파라미터 탐색 + 피처 선택 ("파인튜닝")

탐색 공간 36개 설정: max_depth {2,3,5} × n_estimators {50,200} × learning_rate {0.05,0.1} × subsample/colsample {0.6,1.0} × 피처 선택 k {전체, 50, 20} (mutual information 기준). 평가: **train 내부 시간순 3-fold CV** (test 미사용).

| 구간 | PR-AUC |
|---|---|
| train 내부 CV 최고 설정 (depth=2, n_est=50, lr=0.1, 전체 피처) | **0.1779** |
| CV 2~5위 | 0.1740 / 0.1699 / 0.1653 / 0.1638 |
| (비교) LogisticRegression + 피처 50개 | 0.0784 |
| **CV 최고 설정을 미래 구간 test에 적용** | **0.0682** |
| 튜닝 전 test (실험 1) | 0.0750 |
| 무작위 점수의 test PR-AUC 분포 (몬테카를로 2,000회) | 중앙값 0.0624, **상위 5% 0.1197** |

튜닝 후 test 운영점: Recall ≥0.5에서 Precision 0.086 (기저율 1.58배), Recall ≥0.9에서 0.078 (1.44배).

관찰 두 가지:
1. **train 안에서는 오르고(0.178) 미래에서는 떨어진다(0.068).** 시간에 따라 데이터 분포가 변해서(drift), 튜닝이 과거 패턴을 외우는 쪽으로 작동한다.
2. **어떤 결과도 우연과 구분할 수 없다.** test 불량이 17건뿐이라, 아무 정보 없는 무작위 점수도 PR-AUC 0.12까지 나온다. 튜닝 전(0.075)과 후(0.068) 모두 이 우연 범위 안이다.

## 4. 검정력에 대하여

test에 불량이 17건뿐이라는 것이 근본 제약이다. 표본이 이 정도로 작으면 PR-AUC의 우연 변동 폭이 매우 커서(무작위조차 0.05~0.12를 오간다), 모델 간 0.01~0.05 수준의 차이는 신호일 수도 노이즈일 수도 있다 — 구분할 방법이 없다. 즉 "튜닝으로 0.075를 0.10으로 올렸다"는 주장은 이 데이터에서는 검증 불가능한 주장이다. 이것은 모델링 기술의 문제가 아니라 표본 크기의 문제이며, 튜닝을 더 해도 넘을 수 없다.

## 5. 진단 결론 (3문장)

시간순 분할 기준으로 SECOM의 XGBoost 확률에는 미래 불량을 구분하는 신호가 사실상 없다 (전 구간 Precision이 기저율의 1.0~1.6배). 원인은 두 겹이다 — 시간에 따른 분포 변화(drift)와, 불량 17건이라는 test 표본의 검정력 부족. 따라서 표준 처방(불균형 보정·임계값 튜닝·확률 보정·하이퍼파라미터 탐색·피처 선택)으로는 라우팅에 쓸 만한 확신도 신호를 만들 수 없다.

## 6. 면접용 30초 요약 (구어체)

"SECOM을 메인 파이프라인에 통합하는 대신 스트레스 테스트용으로 역할을 바꿨습니다 (decision). 그냥 감으로 정한 게 아니라 세 단계로 실측했는데요 — 기본 재현에서 Recall 0이 나왔고, 임계값 튜닝과 확률 보정을 해봐도 Precision이 찍기 수준의 1.2배였고, 하이퍼파라미터 36개 조합을 시간순 교차검증으로 돌려봐도 교차검증 안에서만 오르고 미래 구간에서는 오히려 떨어졌습니다. 결정적으로 test에 불량이 17건뿐이라 어떤 개선도 우연과 통계적으로 구분이 안 됩니다 (why). 그래서 'SECOM에서 높은 점수'라는 목표는 포기했습니다 (sacrifice). 대신 이 약한 신호가 에스컬레이션 레이어에 들어갔을 때 시스템이 자동화율 0%로 수렴하며 안전하게 사람에게 넘기는지를 검증하는 용도로 씁니다 — 신호가 나쁠 때 조용히 틀리는 시스템이 제일 위험하니까요."

## 7. 이 기록이 근거가 된 결정

- G1 = (c): 라우팅 레이어의 입력은 신호 출처 중립적인 "이름 붙은 숫자 dict" (AI4I 현존 신호 / SECOM 오프라인 확률 둘 다 수용)
- G2 = (a-1): AI4I = 주 검증, SECOM = 약신호 스트레스 테스트 (합격 기준: 자동화율 0% 수렴 + 자동 처리로 빠져나간 불량 0건 — ADR-009 검증 계획 참조)
